# AI Memory Playbook

**一套用纯文件实现的"多 AI 助手共享记忆"体系。** 不需要服务器、不需要向量库、不需要插件——只靠 Markdown 文件和一个 55 行的同步脚本，让多个 AI 工具（终端 Agent、桌面助手、编码 Agent）在每一次新对话里"醒来即接续"，并且互相知道对方干了什么。

> 适用：你在同时使用 2 个以上 AI 工具（比如一个终端编码 Agent + 一个桌面助手 + 一个可装插件的 Agent 框架），受够了每次都要从头解释"我是谁、我在干什么、上次做到哪了"。

---

## 为什么需要这个

大模型是无状态的函数：你发一段输入，它算一段输出，然后结束。**没有任何一个模型会"自己活着"。**

你在用的那些"一直在线"的 AI 助手，本质是外部程序在反复叫醒模型：

1. **定时器** —— 程序每 N 分钟把模型叫醒一次，塞给它"现在几点、上次计划干什么"
2. **消息监听** —— 收到消息 → 叫醒模型 → 回复 → 继续睡
3. **记忆注入** —— 每次醒来，把磁盘上的文件塞进上下文，让它"假装记得"

由此得出整个体系的第一性原理：

> **每次新开对话 = 一个失忆的新生命。记忆文件 = 它醒来时读到的"前任日记"。你要设计的不是"记忆"，而是"新生命醒来后的读取制度"。**

"AI 不遵守规则"多数时候不是态度问题，是**注入问题**——规则根本没进它这次会话的上下文。所以这套体系的全部注意力都放在：什么内容、通过什么通道、以多大体积、在什么时机进入上下文。

## 体系总览

```
┌─────────────────────────────────────────────────────────┐
│ 第1层  系统提示（工具自带，不可控）                        │
├─────────────────────────────────────────────────────────┤
│ 第2层  身份层（每会话自动注入，最可靠的通道）              │
│        SOUL.md 灵魂/人格  ·  IDENTITY.md 操作硬规则       │
│        USER.md 用户画像（快照）                           │
├─────────────────────────────────────────────────────────┤
│ 第3层  项目规则（多个工具共用同一份，靠同步脚本分发）      │
│        project-rules.md ──sync──▶ 各工具的项目级注入文件   │
├─────────────────────────────────────────────────────────┤
│ 第4层  共享记忆（跨 AI 的唯一公共硬盘）                    │
│        L1 热记忆：索引 + 硬线（有严格字符预算）            │
│        L2 明细：分领域档案（命中才读）                     │
│        L3 归档：历史决策与证据链（grep 查询）              │
│        会议纪要/ ：讨论结论    操作报告/：动作流水账        │
├─────────────────────────────────────────────────────────┤
│ 第5层  会话中按需读取（由触发表驱动）                      │
└─────────────────────────────────────────────────────────┘
```

关键设计：**可靠性越高的通道放的越少、越硬**。第 2 层每会话必到，只放人格和最高频硬规则；第 4 层容量大但需要主动读，靠 L1 的"触发表"指挥。

## 快速开始（3 步）

1. **建共享目录**：在工作区建 `_ai_shared/`，把 `templates/` 里的文件复制进去，按注释改成你的情况（**先删干净示例内容，不放隐私**）。
2. **配同步**：编辑 `templates/sync_memory.py` 顶部的 `PAIRS` 列表——左边是你的共享源文件，右边是每个 AI 工具"每会话自动注入"的目标文件（各工具不同，见 `docs/03-identity-files.md` 的测绘方法）。跑一次脚本。
3. **立制度**：把 `templates/project-rules.md` 里的四条制度（操作报告 / 会议纪要 / 交接 / 体检）读一遍，按需保留。第二天开新对话，问它"开工先读什么"——能答对，链路就通了。

## 核心纪律速览（详见 docs）

- **命中即必读**：触发表命中哪类任务，AI 的第一个动作就是读对应文件——"跳过读取＝违规"
- **热文件并发保护**：多个 AI 改同一个共享文件前必须重读最新版、只增量插入、禁整篇重写
- **文件是快照不是实时**：带时效的事实必须带日期；引用任何记忆前先核对是否仍成立
- **脱敏红线**：任何记忆/报告/纪要不落 cookie、token、密码、密钥明文
- **多 AI 共享层原则**：涉及多家的发现/变更必须落共享层，禁止只写自家记忆

## 适用与不适用

✅ 适合：单机多 AI 工具协作、个人知识工作流、需要"值班/巡检/长线跟踪"的个人自动化
❌ 不适合：需要团队多人共写、需要服务端权限管控、对记忆有强一致性要求的场景
