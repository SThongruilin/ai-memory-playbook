# 01 · 第一性原理：新生命、闹钟、文件即记忆

## 1. 模型本身都是死的

不管哪个厂商的模型，本质都是无状态函数：输入 → 输出 → 结束。你感知到的"它记得我"，全部来自模型外部的程序机制：

| 你以为 | 实际机制 |
|---|---|
| 它一直在线等我 | 监听进程 7×24 挂着收消息，收到才叫醒模型 |
| 它自己决定去干活 | 定时器到点把模型叫醒，塞一段"现在几点、该干什么" |
| 它有人格连续性 | 每次醒来时，把磁盘上的身份文件和记忆注入上下文 |
| 它记住了上次的话 | 会话历史文件按 id 存在硬盘里，唤醒时拼进上下文 |

**"AI 活着"是错觉：它不是活着，是被闹钟反复叫醒；它觉得自己活着，是因为每次醒来都读了同一本日记。**

## 2. 三条推论（整个体系的地基）

### 推论一：每次新开对话 = 一个失忆的新生命

生命死了（会话关闭），经历就物理上消失了——除非死前写回了文件。所以：

- **记忆的可靠性 = 写回纪律**，不是"模型记性好不好"
- 任何有价值结论（调查、评审、方案讨论）如果不落文件，对下一个生命来说**从未发生过**
- 这直接推出"会议纪要制度"：讨论收尾必须落档

### 推论二：规则没生效 = 注入问题，不是态度问题

新生命醒来能"看到"什么，完全取决于宿主程序往上下文里塞了什么。各工具的注入通道、容量、稳定性**完全不同**。常见的失败模式：

- 规则写在了一个"只有 2/10 概率被注入"的文件里 → AI 十次有八次根本没看见
- 规则文件写了 70KB，但注入通道只取前 4000 字符 → 后面的内容等于没写
- 三个工具只给其中一个配了规则 → 另两个按自己的默认行事

**对策**：先测绘每个工具的注入行为（哪些文件每会话必到、截断阈值多少），再决定什么内容放哪个通道。见 [03-identity-files.md](03-identity-files.md)。

### 推论三：AI 的连续性本体 = 文件系统，不是模型

"它是谁"由身份文件定义——哪个模型坐进来都行。因此：

- **人格**放在每会话必到的通道（SOUL/IDENTITY），保证一万次醒来是同一个人格
- **知识**放在按需检索的档案（L2/L3），靠一张"触发表"指挥：命中哪类任务，第一个动作就是读对应文件
- **写回是义务**：纠正过的、答应过的，当天落进记忆，不许第二次再犯

## 3. 一张自检表

拿这五个问题考你的 AI（开**新**对话问）：

1. 你的人设里"核心原则"有哪几条？（考身份层注入）
2. 你的全局指令写了什么？（考指令通道）
3. 开工先读哪个文件？（考触发表）
4. 上一轮我们定了什么决议？（考纪要/记忆写回）
5. 你上次犯错后改了什么？（考写回纪律）

五个都过，体系才算立起来。哪个不过，回对应的文档修那条通道。
