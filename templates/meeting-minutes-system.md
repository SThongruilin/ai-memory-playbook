# 会议纪要制度（多 AI 通用）

## 为什么有这个制度

每次新开对话 = 一个失忆的新生命，它只能读到上次留下的文件。操作报告记"**干了什么**"
（单次操作流水账），会议纪要记"**得出了什么**"（结论、判据、待办）。一场重要讨论如果不
落成纪要，会话关闭后这段成果就物理上不存在了。

## 触发

1. 调查 / 评审 / 方案对比类对话**收尾时**——哪怕全程没改动任何文件
2. 跨 AI 协作的事项定下来时（互审结论、拆解定案、制度变更）
3. 主人说"记一下 / 出纪要 / 落档"时

纯闲聊、单步小问答不写。宁可漏一份，不可滥十份。

## 位置与命名

- 目录：`_ai_shared/meeting-minutes/`
- 命名：`主题_生成者_v<版本>_<YYYY-MM-DD>.md`（生成者署自己的名）

## 格式（照抄，缺项写"无"）

```markdown
# 会议纪要：<主题>
- 时间 / 参会：<日期；哪家 AI 记录>
- 一句话结论：
- 关键事实与判据：（带来源 / 路径 / 数字，可被反驳的那种，不写感想）
- 决议与待办：（谁、做什么、截止）
- 遗留疑问：（下次会话带入）
```

## 规矩

- 结论必须写成"可被反驳的判据"，不写心得体会
- 引用别家 AI 的工作注明来源文件；**执行者未署名的标"待认领"，不替别家认领**
- 同日补充**原地追加**并标注时间与版本号（文内 v+0.1）；跨日或重大修订另立新文件，旧文件不删
- 带时效的事实（余额、截止、临时状态）必须带日期；引用旧纪要前先核对是否仍成立
- **脱敏**：纪要不落 cookie、token、密码、API key 明文
- 与 HANDOFF 的分工：HANDOFF = 单个任务的交接班记录；纪要 = 一场讨论的知识沉淀
